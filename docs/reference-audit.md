## 1. Purpose, date, environment

**Purpose.** FrameKeeper (repository `fengk623/polaroid-autocrop`) learns from two public projects:

- **SpektraLab**: its development process, its macOS interface, and its Windows Qt Quick front end. We reference process and user-interface ideas only, never code.
- **PhotoFrame / Encadré**: its observable behaviour for adding synthetic borders.

This document does four things:

- It records exactly what was read in each project, at which commit.
- It classifies every SpektraLab process rule found by the earlier audit passes against FrameKeeper's own process decisions (§5).
- It records contradictions, gaps and licence constraints.

The interface element table, with concrete FrameKeeper values, is in `docs/ui-reference.md`.

**Date.** 2026-10-28. Line citations refer to the commits in §2 and will drift as those repositories move.

**Auditor.** An automated agent session working from three audit notes prepared earlier the same day (passes A–C), with spot checks against the clones (pass D). Nothing here is a legal opinion.

**Environment.**

- GitHub was reachable through `git`, so both repositories were cloned read-only under `refs/`. Fetching github.com pages with WebFetch was blocked by robots rules for the SpektraLab tree pages, which is why the repositories were cloned rather than browsed.
- The clones use a partial-clone filter (`blob:limit=2097152`). Blobs over 2 MiB are fetched on demand at checkout, and the checked-out trees are complete: for example, the 5 MB screenshots are present.
- No file in either reference repository was modified.

## 4. SpektraLab UI reference summary

The full element-by-element table, with our decisions and concrete values, is in `docs/ui-reference.md`.

**What we take.** The information architecture of the macOS app:

- **Layout.** Three flush regions (left rail, centre canvas with a top bar and a bottom filmstrip, right rail), separated by 1 px hairlines in two tiers rather than by gaps or radii. Rails can be resized, folded and reset.
- **Accent.** One accent colour that means only "selected / look here".
- **Disabled controls.** A row is disabled as a whole, with the reason in a tooltip; pointer targets are 28 px whatever the ink size.
- **Badges.** A badge stack in the canvas corner tells the truth about Preview versus Full resolution, and a refusal is a visible event.
- **Canvas.** The split compare is anchored to the picture, not the viewport. 100 % means one image pixel per device pixel. Sampling is nearest-neighbour from 100 % up. Double-click toggles fit and 100 %.
- **Rule.** Every surface that shows the frame shows the canvas's frame.

**What we take from the Windows Qt Quick front end.** These are patterns, re-implemented and never copied:

- a single controller object exposed to declarative QML;
- a serial or bounded worker with generation and revision tags, so a superseded result never replaces the display;
- a custom `QQuickItem` canvas with an explicit physical 100 %, pixel-grid snapping and nearest/linear switching;
- one geometry module for preview, navigator and export;
- atomic, no-overwrite publication;
- an offscreen `--self-test` with named checks and a JSON report.

It also records the Windows platform choices we adopt: the native title bar, Ctrl in place of ⌘, F11 for full screen, single-key shortcuts that are not menu accelerators, and system fonts.

**What we do not take.**

- SpektraLab's visual signature: the warm `#E1A95F` accent on `#2D2D2C` rails over a `#5F5F5F` surround, all-bold SF Pro type, white-capsule list selection, and accent-outlined action capsules.
- Its names, strings, icons, assets and identifiers (§8).
- The domain sections (film, print, enlarger and so on).

**Notes on our paths**

- Paths follow the repository layout in `AGENTS.md` §1:
  - `core/` is the Qt-free C++20 library `fkcore`. Public headers are in `core/include/fk/`, sources in `core/src/`, and modules are named `core/<module>` in ARCHITECTURE §2.
  - `app/` is the Qt Quick app, and `platform/` holds the per-OS adapters.
  - `tools/cli` is `fkcli`, and `tools/fixtures` is `fkfixture`.
  - The repository tools are `tools/run-tests.sh`, `tools/test_report.py`, `tools/check-docs.py` and `tools/check-repo.py`. `tools/release/` holds the release scripts (RELEASE-CHECKLIST).
  - The tests are in `tests/core`, `tests/contract`, `tests/app` and `tests/integration`.
  - The workflows are `.github/workflows/{ci,nightly,release}.yml` (ADR-0013).
- A name not yet fixed by any existing document is a proposal: for example `tests/contract/data/geometry_pairs.json`, `app/i18n/terminology.md`, `docs/screenshots/` and `tools/capture-live.sh` (the last is named in HV-02).
