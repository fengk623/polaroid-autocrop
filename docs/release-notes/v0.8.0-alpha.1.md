## 本版新增 / 修复

- **图库**：一个以 `.fklibrary` 结尾的普通文件夹，里面有 `catalog.fkproj`（与工程同一种格式）、`library.json`（名称、封面、文件夹、排序）、`catalog.fkproj.bak`、`backups/` 历史（每小时最多一份，保留 10 份）、写入时的 `library.lock`，以及可随时删除的 `cache/`。扫描件和调色图留在原处，图库只引用它们。
- **文件菜单**：新建图库…（默认放在“文稿”，可换位置）、打开图库…、将工程导入为新图库…；都会先询问未保存的修改。把图库文件夹拖进窗口也会打开它。
- **旧工程导入为副本**：先检查（损坏、由更新版本保存、同名文件夹已存在、磁盘空间不足时拒绝；找不到的扫描件只计数），写入临时文件夹、读回比较后再改名到位；任何一步失败都不留下文件。工程文件和它的 `.bak` 只被读取，之后照样能直接打开；以前导出的调色图照样能回导（图库沿用工程 ID）。
- **两个 FrameKeeper 同时打开**：后打开的以只读方式打开，并说明是哪台电脑、哪个用户；3 分钟没有心跳（同一台电脑上进程已结束时立即）的锁，询问后才接管；被别处接管后这里变为只读，可以“另存为”工程文件保住修改。
- **损坏与恢复**：目录文件损坏时，询问后从最近保存的可读副本（`.bak` 或 `backups/`）恢复，损坏的文件改名保留；`library.json` 损坏时用它的 `.bak`，再不行就由目录重建。恢复快照按图库区分，恢复时回到同一个图库。
- **评级与标签数据**：相纸和扫描件新增图库数据（星级、选取、颜色/文本标签、手动顺序、加入时间），只在设置过时写入；旧版本原样保留。界面在 U020 加入。
- **相对路径**：工程与图库的 `relPath` 一律写成 `/`；以前在 Windows 上写的 `\` 路径在 macOS / Linux 上也能解析。
