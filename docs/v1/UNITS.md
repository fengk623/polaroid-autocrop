### U004 目标优先回导与证据模型
- 工单：UX-07（主体）；关联 FK-007。
- 范围：选中目标相纸 → 选任意文件 → 确定导出版本（多个版本时由证据或用户选择）→ 兼容性验证（尺寸、方向、色彩、内容）→ 预览确认 → 关联。批量回导：嵌入 ID、内部导出记录、文件名、内容签名作为证据评分；歧义必选、冲突必示，绝不自动错配。无本项目导出历史的编辑图可明确建立新对齐关系，不伪造历史。只替换确认的 Inner 内容。RFC-0006 修订。
- 验收：同名、改名、移文件夹、XMP 保留/丢失、无侧车、一次多文件、多个导出版本、保存重开、重启后（工程已保存）均按规则完成；无歧义样本成功率 100%；歧义不自动错配；未修改 TIFF 往返在规定条件下逐像素一致，修改后 Inner 外像素不变（同色彩空间、位深、可比较几何）。
- 实现：RFC-0006 §Relink v2。核心 core/src/relink_assess.cpp（`describeGradedFile`、`assessRelink` 证据评分与 unique/ambiguous/none 判定、`alignmentGeometry` 新建对位形状、`signatureOfExport` 按导出几何从预览取样、`alignmentRecord`；记录 `origin: "manual_alignment"`）；编辑软件后缀增加 `_n`。应用：`relinkFiles(urls, target, update)`、`relinkTargets`、`dropFiles`（拖入分流）、`applyRelink` 新建对位；回导对话框（候选、证据 ✓/✗、指定为…重新检查）；右栏“回导到这张相片…”；回导入口在有相片时即可用。
- 设计细化：新建对位的宽高比容差由 RFC 初稿的 ±2% 改为 0.5%（与合成缩放容差一致，否则只能拉伸）；形状按“尺寸完全一致 → 宽高比更接近 → 画面”选择裁切或拉正。
- 测试：核心 `RelinkV2.*` ×12；自检 9 项（替换 3 个 UX-07 已知问题）；含“新会话中经新建对位合成，与整张相片导出逐像素一致”。

### U005 回导变换：旋转/缩放/裁切分离并持久化
- 工单：FK-002；关联 UX-07。
- 范围：确认的 0/90/180/270° 与缩放、裁切分别保存在关联记录中，预览与输出直接使用；方形/对称/低纹理方向不可靠时请用户指定；外部裁切检测，不静默拉伸；历史导出几何版本化。
- 验收：非对称矩形/方形 × 四种旋转、缩放、重开工程均正确；known-issue FK-002 转为常规测试。
- 实现：RFC-0006 §Confirmed transform。`checkEdited` 先按尺寸限定可能的旋转（{0,2}/{1,3}/正方形四个/无=另行裁切），再比画面；最佳方向通过阈值且领先其余可能方向 ≥0.15 才算可靠，否则动作 `choose_rotation`，由用户在回导对话框“方向”中选择（未选不能勾选，`applyRelink` 也拒绝）。勾选即确认旋转、缩放、较低位深，保存为 `edits[].relinked.transform`；合成预览与最终输出按保存值使用、不再重新猜测（原 `sizeMatches ? 0 : suggestedRotate` 的缺陷）；关联后尺寸变化则拒绝输出。旧版本关联（无 transform）只在画面能明确判断方向时使用。
- 附带修复（U004 界面）：回导对话框下拉框的选中项绑定在模型变化后不更新（唯一匹配仍显示“选择相片…”）——改为按模型计算索引；自检截图发现。
- 附带（测试）：已知问题检查的前提不满足时记为“不适用”（8 位扫描上的 FK-010、没有数量提示时的 UX-01），不再误报“不再复现”。
- 测试：核心 `RelinkTransform.*` ×3；自检 FK-002 5 项（替换已知问题）、回导场景 R7。
- 分支 `unit/U005-relink-transform`（基于 U004）· PR #7（所有者合并）· 不单独发布。

### U006 缺失 ICC 的明确解释与持久化
- 工单：FK-003。范围：无 ICC 的调色图提供“按导出 ICC 解释 / 选择 ICC / 取消”，保存选择与可解析配置字节，只转换一次；无效配置不静默猜测。
- 验收：Adobe RGB 扫描 → sRGB 导出 → 编辑去 ICC 后按用户确认正确合成；跨空间、无效配置、重开工程；边框不变。
- 实现：RFC-0012 §Graded files without a usable profile。`checkEdited` 区分缺失/无法读取（`choose_icc`）；`iccChoicesFor` 只按 SHA-256 识别导出时的配置（扫描件配置、内置 sRGB/Adobe RGB、工程已存配置），另可选扫描件配置、sRGB、Adobe RGB、配置文件（`loadIccProfile` 校验）；缺失且已识别时预选“导出时的配置”，无法读取时不预选；勾选确认，未选择时 `applyRelink` 拒绝；选择存入 `relinked.transform.iccSource/iccSha256`，配置字节存入工程顶层 `iccProfiles`（加载时按 SHA-256 校验）；`gradedProfile` 决定合成用的配置，旧版本关联只在能识别导出配置时使用，否则报错要求重新关联。
- 测试：核心 `GradedProfile.*` ×3（Adobe RGB 扫描→sRGB 导出→去配置：按确认解读平均误差 0.0000，按扫描件空间解读 0.0096，边框不变；无法读取/无法识别不猜测；随工程保存）；自检 FK-003 4 项（预选导出配置且需确认、未选择不关联、保存于关联与工程、输出与整张相片平均差 0.00000）。工具：check-i18n 也合并核心错误信息中的相邻字符串。

### U007 扫描件与调色图的身份校验
- 工单：FK-007。范围：打开与输出前流式核对源身份（非 UI 线程）；调色文件被覆盖后重新检查内容、尺寸、旋转、ICC；校验与读取之间文件改变即失效重验。
- 验收：同名同尺寸替换、内容修改、改名、移动、正常再次调色被正确区分；known-issue FK-007 转为常规测试。
- 实现：RFC-0009 §Source identity。导入时在识别任务中流式计算整个扫描文件的 SHA-256（旧工程在下次打开扫描件时补上）；`verifyFileIdentity`（大小 → 首尾 1 MiB → 全文件）在预览、识别和全部输出任务中、读取前于后台运行；`resolveScanPaths` 加载时只比大小；`verifyScans` 全部流式核对。改动的扫描件（`changed`）不加载、不再识别，列表显示原因，“重新定位…”按指纹找回。输出任务读取前后比较 `FileStamp`（大小 + 纳秒级修改时间），中途改动则丢弃输出；调色文件同样。调色文件哈希不同时 `recheckGraded`：尺寸、确认方向下的画面（≥0.80）、内嵌配置（本版开始记录）相同 → 视为再次调色，使用并记录新哈希、提示；否则按原因拒绝。
- 限制：“重新定位…”仍在界面线程上对候选文件做首尾指纹（与以前相同）。
- 测试：核心 `SourceIdentity.*` ×5（含原已知问题）；自检 FK-007 6 项（在扫描件副本上；拒绝时检查提示原因）。
- 分支 `unit/U007-source-identity`（基于 U006）· PR #9 · 不单独发布。

### U008 统一数据保护、恢复快照与备份恢复
- 工单：FK-001、FK-008；关联 UX-05。

### U026 格式能力与 DNG 互操作（FK-012）
- 范围：按 FORMAT-MATRIX 的评审结论实现/提示；DNG 独立解码验证；16-bit TIFF 为可靠往返母版；未验证的第三方格式不宣称支持。

- 顺序：不依赖图库，版本号按完成顺序为 v0.7.0-alpha.10（原计划 v0.9.0-beta.1）。
- 实现：CI（Core linux）用独立解码器 LibRaw（rawpy，仅测试用，装在 venv 中）解码本软件导出的线性 DNG，与同一画面区域的 16 位 TIFF 导出比较（每通道增益 ±5%、相关 ≥ 0.995、增益后平均误差 ≤ 1%），结果写成 CI 注记；回导与拖入线性 DNG 时明确拒绝并说明“请导出 16 位 TIFF”，不会被当作扫描件导入。PRD F05 A5 原写“与 TIFF 相差 1 LSB 以内（test_dng）”从未实现，已改为实际检查。
- 建议（待所有者确认）：v1.0 不支持 DNG 回导——这是本软件给 RAW 工作流的导出格式，调色后的母版用 16 位 TIFF；读取本软件自己的 DNG 技术上可行，但其他软件另存的 DNG 不一定是 LinearRaw，范围与成本不确定。
- 测试：`TiffRead.LinearDngIsRefusedWithGuidance`（先红后绿）；自检 “FK-012 a Linear DNG given back …”（回导与拖入；无配置文件的扫描件跳过，因为无法导出 DNG）；CI LibRaw 解码。
- 未完成：Capture One / Photoshop / Lightroom 的打开与回导记录需要真实软件（所有者）。
