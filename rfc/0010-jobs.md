# RFC-0010 — Jobs and threading

Status: Accepted · Module: `app/src/Jobs.cpp` (the job runner lives in the app; core functions take a cancel token and a progress function) · PRD F10 · Tests: self-test `runTaskSafety`, `runMemoryBudget`

- `CancelToken` (atomic flag + optional deadline); every long loop polls it per band/row block.
- `JobQueue` with named lanes and limits: `export` (1), `detect` (2), `thumb` (2), `io-light` (2); a job
  declares `estimatedBytes`; the queue does not start a job when `inUse + estimate > budget`
  (budget from `MemoryBudget`, ADR-0007), except when nothing else runs (progress guaranteed).
- `Generation` counters per (item, purpose); results carrying an older generation are dropped by the consumer.
- Debounce helper for UI-driven recomputation (default 150 ms idle before a Full-resolution job).
- Progress callbacks are throttled (≥ 50 ms) and never call into UI code; the app marshals to the UI thread.
- Thread-safety: `ImageSource` instances are not shared between threads; each job opens its own (cheap).

## Implementation notes (v0.5.0)

- The queue lives in the app layer (`app/src/Jobs.{hpp,cpp}`, `JobRunner`) on `QThreadPool`s, not in the core;
  the core only provides `CancelToken` and progress callbacks. Lanes: `detect` 1, `export` 1, `io` 2
  (full-resolution canvas detail, thumbnails, composite previews, relink checks).
- One detection at a time instead of two keeps peak memory inside the 8 GB device budget
  (PERFORMANCE-BUDGET: a 1600 DPI detection peaks at ≈ 320 MB, an upright export at ≈ 560 MB) without an
  admission check. Revisit if lanes widen.
- **Memory reservations (U017, FK-005):** `JobRunner::start(…, estimateBytes)`. The runner reports
  `reservedBytes()` = per lane, the largest estimates of its queued and running jobs, as many as the lane runs
  in parallel; the controller reserves that amount in the cache budget (`fk::CacheLedger`, RFC-0014 §Memory
  budget) from the moment a job is queued, so caches make room before its work starts, and releases it after
  `done`. Jobs are not held back by the budget (the lanes bound concurrency; an admission check that waits is
  still not implemented). Estimates: detection / opening a scan, composite preview, exports, relink checks
  (RFC-0014).
- Results reach the UI with `QMetaObject::invokeMethod(…, Qt::QueuedConnection)`; canvas detail and composite
  previews carry generation numbers and stale results are dropped.

## Task safety (v0.6.0-alpha.2, U002, FK-006 part 1)

Status: Accepted (2026-10-30). Owner's review §10: the minimal framework comes before any relink, preview or
recovery work so later units do not need to retrofit it.

**States.** Every job ends in exactly one state: `succeeded`, `failed`, `cancelled` or `outdated`; before that it is
`queued` (waiting for a lane) or `running`. A late progress report never reopens a finished job. The job list
shows each state; a failure shows its message. `failed` comes from `JobContext::fail()` (worker) or from the `done`
callback returning `JobApply::failed` (e.g. "3 of 5 exports failed"); "done" is never shown for a failure.

**Generations.** The controller keeps counters: `projectGen` (bumped by New/Open/Close project), `scanGen[scan]`
(detection applied, scan removed, any print of the scan edited), `itemGen[item]` (outline, inner shape, upright,
relinked file, undo/redo, reset) and `compositeGen` (mask mode, feather, preserve-edge). A job captures a
`JobSnapshot` of the counters it depends on when it starts; its `done` callback applies the result only if they are
unchanged and otherwise returns `JobApply::outdated`, writing nothing.

| Job | Depends on | If outdated |
| --- | --- | --- |
| Detection | project, scan | Not applied; the user's edits made meanwhile are kept; a notice says to detect again |
| Open scan (preview) | project | Dropped |
| Snap to edges | project, item | Dropped (the user's newer outline wins) |
| Composite preview | project, item, composite | Dropped; requests for the same print are coalesced: at most one in flight per print — a newer request cancels it and is served once it has stopped, with the state as it is then (U016, UX-09: no backlog while a value is dragged) |
| Export image areas / full prints / final | project | Files already written stay on disk (they are complete outputs); nothing is recorded in a project opened after the export started; a notice says so |
| Relink check | project | Rows are not shown |
| Full-resolution canvas detail | canvas view generation | Dropped by the canvas (unchanged) |

Export records keep their own geometry snapshot (the geometry that was exported), so a later edit of the print does
not make a finished export's record wrong; only a replaced project does.

**Cancellation.** New/Open/Close project cancels every job (as before). Cancellation reaches the core through the
`CancelToken`; sinks write to `<name>.fk-tmp-<random>` and remove it on abort, so a cancelled export leaves no temporary
files (self-test TS3).

**Test hook.** `JobRunner::setTestDelayMs()` delays each job's work so the self-test can change state while a job
is in flight; it is 0 in the product.

**Verification.** Self-test TS1 (mask changed during a composite preview → `outdated`, no preview stored; a fresh
request matches the current item generation), TS2 (print edited during re-detection → `outdated`, edit kept), TS3
(project opened during an export → `cancelled`, no `*.fk-tmp-*`), TS4 (unreadable TIFF → `failed`). With the
freshness checks removed, TS1 and TS2 fail (stale preview stored; the edit is silently replaced by the detection
result) — recorded in docs/v1/WORKLOG.md.

**Not in this unit (U017):** byte-accounted budgets, reservation before start, cache eviction, bounded queues.
